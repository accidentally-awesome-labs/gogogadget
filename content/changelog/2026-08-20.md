title: Staff roles, portability, and revenue recovery
date: 2026-08-20
summary: A read-only support tier, SEO that fixes a real duplicate-content bug, org-level data export, a dunning sequence — and a live notification stream that had never connected.
---

### Added

- **Support role tier.** Staff access is now a role (`support` / `admin`)
  rather than a boolean: support reads every admin dashboard and can change
  nothing. The write boundary is one method-based guard, so admin routes added
  later inherit it instead of silently missing it. Role grants are audited,
  and the last full admin cannot be demoted.
- **Org-level data export** — an `org:admin` JSON bundle (members, projects,
  file metadata, audit log, billing state, API and webhook inventory)
  delivered through the job → storage → notification path. Secrets are
  excluded by construction: rows map to explicit DTOs, because the token hash
  and webhook signing secret columns would otherwise have been serialised
  straight into a file customers download.
- **Dunning sequence** — day 0, +3, +7. Both follow-ups are scheduled at the
  moment of failure and re-read the subscription before sending, so a customer
  who fixes their card on day 4 never receives the day-7 warning.
- **SEO hardening** — self-referential canonicals, reciprocal hreflang,
  Organization/WebSite/BlogPosting JSON-LD, `lastmod` in the sitemap for dated
  content, and RSS autodiscovery.

### Fixed

- **The live notification stream never connected.** The vendored SSE extension
  targets htmx 2 and registers through an API htmx 4 removed, so the script
  threw on every authenticated page load and the badge only ever updated on
  navigation — while the endpoint worked perfectly. Replaced with a native
  `EventSource`, one fewer dependency.
- Every public page was reachable at three URLs (`/`, `/?lang=en`,
  `/?lang=es`) with identical content — duplicate content introduced the day
  the locale switcher shipped, now collapsed by canonicals.
- Export storage keys used a second-granularity timestamp, so two exports for
  one organization inside the same second overwrote each other's object while
  both rows survived.
- The in-app payment-failure notification sat inside the email gate, so an
  organization whose owner-email lookup failed got no warning at all.
