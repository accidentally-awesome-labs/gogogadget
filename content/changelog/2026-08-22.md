---
title: Editable content
date: 2026-08-22
summary: Blog posts and changelog releases now live in Postgres and are edited in-app — and a new content type is one Go value, with no migration.
---

### Added

- **A content-type registry.** Blog posts and changelog releases used to be
  markdown embedded in the binary: changing a typo meant a commit and a deploy.
  Both are now rows in `content_entries`, authored at `/admin/content`. The
  extension point is `content.Type` — declare one and the admin list, the
  editor, validation, revisions, publishing, caching, the public index and
  detail routes, and sitemap and RSS inclusion all follow. **No migration, no
  new table, no new handler, no new template.** `kind` deliberately carries no
  CHECK constraint and type-specific fields live in a `meta` JSONB blob, which
  is what removes the per-type DDL. A type with `Path: ""` gets admin CRUD and
  programmatic reads with no public route at all — that is how in-app copy,
  help snippets, and legal text are managed.
- **Scheduling and expiry with no worker.** Visibility is a SQL predicate over
  `published_at` and `unpublish_at`, so a future date *is* the scheduled state
  and a past expiry *is* the retired state. Nothing to enqueue and nothing that
  can dead-letter; the cost is that a transition lands within one 30s cache TTL
  of its moment.
- **Language variants per entry.** Every row carries a `locale`: `''` serves
  every reader, and an `es` row wins for Spanish ones. The `hreflang` alternates
  the sitemap has always advertised now point at content that can genuinely
  differ. This is not a translation workflow — no side-by-side editing, no
  stale-translation tracking — those attach to this column later if they earn it.
- **Revisions and media.** Every save snapshots the previous state, so restoring
  is itself a save. `/admin/media` uploads images for content bodies, keyed off
  the sniffed bytes rather than the client's declared type, and served with
  `Content-Disposition: inline` — the one place uploads are rendered instead of
  downloaded. SVG is excluded on purpose: it can carry script and would execute
  same-origin.

### Changed

- **The markdown corpus is now a seed, not a read path.** `content/blog` and
  `content/changelog` stay in the tree and are imported by `make seed`,
  idempotently and without ever overwriting a row an operator has edited. Docs
  stay embedded markdown and are deliberately *not* a content type: they must
  version with the binary they describe.

### Fixed

- `make seed` is re-runnable. Three fixtures guarded duplicates with
  `ON CONFLICT DO NOTHING` against tables that have only an identity primary
  key, so the clause caught nothing; the active-announcement insert then failed
  the whole file, which was the only thing hiding the duplication.
